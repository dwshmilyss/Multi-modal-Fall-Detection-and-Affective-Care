# 跌倒检测算法优化文档

> 本文档记录 `deidao/detector.py` 中跌倒检测算法的所有优化方案、实现细节和调优参数。

---

## 一、原始算法（优化前）

### 核心逻辑

原始算法使用**单一躯干角度阈值**判定跌倒状态：

| 角度范围 | 判定状态 |
|----------|----------|
| < 20° | 站立 (Normal) |
| 20° ~ 50° | 跌倒中 (Falling) |
| > 50° | 平躺 (Lying) |

### 问题

- **单帧判定**：只看当前帧角度，极易误报
- **弯腰误报**：弯腰捡东西时角度 > 35°，立即触发报警
- **无法区分坐下**：坐下过程角度变化与跌倒相似
- **无时间维度**：不考虑动作的连续性和速度

## 二、高优先级优化（已实现）

### 优化1：时间序列分析（滑动窗口 + 角速度）

**原理**：跌倒时躯干角度变化很快，弯腰时变化缓慢。

**实现**：
- 滑动窗口大小：`ANGLE_WINDOW = 15` 帧
- 角速度计算：`angular_velocity = abs(angle[-1] - angle[-3]) / 2.0`（度/帧）
- 阈值：`ANGULAR_VEL_THRESHOLD = 3.0`（从 2.0 提高到 3.0，减少弯腰误报）

**效果**：
- 缓慢弯腰：角速度 < 1°/帧 → 不触发
- 快速跌倒：角速度 >> 3°/帧 → 触发

### 优化2：头部高度变化检测

**原理**：跌倒时头部快速下降，弯腰时头部下降较慢。

**实现**：
- 头部窗口：`HEAD_WINDOW = int(min(fps * 1.5, 45))`（约 1.5 秒）
- 下降速率：`head_drop_per_sec = (nose_y[-1] - nose_y[-lookback]) / lookback * fps`
- 阈值：`HEAD_DROP_THRESHOLD = 0.30`（头部下降超过身高 30%/秒）

### 优化3：宽高比变化检测

**原理**：跌倒时人体 bounding box 从"高瘦"变"矮胖"，宽高比突变。

**实现**：
- 记录宽高比历史：`bbox_ratio_history`（15 帧窗口）
- 变化倍数：`bbox_ratio_change = current_ratio / old_ratio`
- 阈值：`BBOX_RATIO_CHANGE_THRESHOLD = 1.5`

### 优化4：连续帧确认

**原理**：真实跌倒会持续多帧，误报通常是单帧或少数几帧。

**实现**：
- 连续确认帧数：`FALL_CONSECUTIVE = 5`
- 只有连续 5 帧都满足跌倒条件才报警
- 非候选帧时递减：`fall_candidate_frames = max(0, fall_candidate_frames - 1)`

## 三、中优先级优化：坐姿检测（解决坐下误报）

### 问题

坐下过程与跌倒特征相似：
- 躯干角度增大（25°~70°）
- 头部快速下降
- 宽高比变化

### 方案1：髋部高度检测

**原理**：坐下时髋部停在椅子高度（身高 35-55%），跌倒时髋部降到地面（<25%）。

**实现**：
```python
# 髋部Y坐标（全帧）
hip_y_full = y1 + kalca_merkezi[1]
# 髋部高度占身高比例（0=头顶，1=脚底）
hip_height_ratio = (y2 - hip_y_full) / max(estimated_body_height_px, 1)

# 坐姿判定
if 0.35 <= hip_height_ratio <= 0.55 and 25 <= torso_aci <= 70:
    current_durus = "坐姿 (Sitting)"
```

**参数**：
- `HIP_HEIGHT_SITTING_MIN = 0.35`（坐姿髋部下限）
- `HIP_HEIGHT_SITTING_MAX = 0.55`（坐姿髋部上限）
- `HIP_HEIGHT_FALLING = 0.25`（跌倒髋部上限）
- `SITTING_ANGLE_MIN = 25`（坐姿角度下限）
- `SITTING_ANGLE_MAX = 70`（坐姿角度上限）

### 方案2：宽高比坐姿检测

**原理**：坐着时人"矮胖"（宽高比大），站立时人"高瘦"（宽高比小）。

**实现**：
```python
# 坐姿宽高比下限（坐着时人矮胖，宽高比大）
SITTING_BBOX_RATIO_MIN = 0.7
# 坐姿角速度上限（坐着时稳定，角速度低）
SITTING_ANGULAR_VEL_MAX = 0.5

# 坐姿判定（端正坐着）
if bbox_ratio >= 0.7 and torso_aci < 25 and angular_velocity < 0.5:
    current_durus = "坐姿 (Sitting)"
```

**为什么用 3 个条件**：
- 仅宽高比≥0.7：站立时也可能达到（摄像头角度影响）
- 加角度<25°：坐得很端正时角度很小
- 加角速度<0.5：坐着时应该很稳定

### 坐姿检测综合逻辑

```python
# 坐姿判定（两个条件满足其一）
if (0.35 <= hip_height_ratio <= 0.55 and 25 <= torso_aci <= 70) or \
   (bbox_ratio >= 0.7 and torso_aci < 25 and angular_velocity < 0.5):
    current_durus = "坐姿 (Sitting)"
    fall_candidate_frames = 0
    is_fall_candidate = False
```

## 四、弯腰误报优化（方案A+B+C）

### 问题

弯腰和跌倒有相似特征：
- 躯干角度都会变大（可能>35°）
- 头部都会快速下降
- 宽高比都会变化

### 方案A：恢复检测

**原理**：弯腰后会恢复站立，跌倒不会。如果角度从大变小（恢复），立即清除候选帧。

**实现**：
```python
# 在连续帧确认后添加
if torso_aci < 25 and fall_candidate_frames > 0:
    # 角度恢复到<25°，说明是弯腰后恢复，清除候选帧
    fall_candidate_frames = 0
    print("[调试] 检测到恢复动作（角度<25°），清除候选帧", flush=True)
```

**效果**：弯腰后恢复不会累积候选帧，避免误报。

### 方案B：提高角速度阈值

**原理**：快速弯腰很难达到很高的角速度，但跌倒可以。

**修改**：
```python
ANGULAR_VEL_THRESHOLD = 3.0  # 从 2.0 提高到 3.0
```

**效果**：减少快速弯腰的误报，但可能漏检慢速跌倒（老人跌倒可能较慢）。

### 方案C：髋部下降速率检测

**原理**：弯腰时髋部位置稳定，跌倒时髋部快速下降。

**实现**：

1. 新增髋部Y坐标历史：
```python
hip_y_history = deque(maxlen=ANGLE_WINDOW)  # 髋部Y坐标历史
```

2. 记录髋部Y坐标：
```python
hip_y_history.append(hip_y_full)  # 每帧记录髋部Y坐标
```

3. 计算髋部下降速率：
```python
HIP_DROP_THRESHOLD = 100  # 髋部下降速率阈值（像素/秒）
hip_drop_per_sec = 0.0
if len(hip_y_history) >= 5:
    hip_drop_rate_px = (hip_y_history[-1] - hip_y_history[-5]) / 5
    hip_drop_per_sec = hip_drop_rate_px * fps
```

4. 修改特征1和特征2，加入髋部下降要求：
```python
# 特征1: 角度大 + 角速度高 + 髋部快速下降
if torso_aci > 35 and angular_velocity > 3.0 and hip_drop_per_sec > 100:
    triggered_features.append("angle_vel_hip")

# 特征2: 头降快 + 髋部快速下降
if head_drop_per_sec > 0.30 * body_height and hip_drop_per_sec > 100:
    triggered_features.append("head_hip_drop")
```

**效果**：弯腰时髋部稳定（<100px/s），不会触发；跌倒时髋部快速下降（>100px/s），正常触发。

## 五、多特征共识机制

### 原理

单特征容易误报，要求**至少 2 个特征同时触发**才认为是跌倒。

### 特征列表

| 特征编号 | 特征名称 | 触发条件 | 权重 |
|----------|----------|----------|------|
| 1 | 角度+角速度+髋部下降 | 角度>35° 且 角速度>3° 且 髋部降>100px/s | 高 |
| 2 | 头降+髋部下降 | 头降>30%身高/秒 且 髋部降>100px/s | 高 |
| 3 | 宽高比突变 | 宽高比>1.5x 且 角度>35° | 中 |
| 4 | 髋部过低 | 髋部<25%身高 且 角度>35° | 中 |

### 判定逻辑

```python
triggered_features = []  # 记录触发了几个特征

# 检查每个特征
if 特征1触发:
    triggered_features.append("angle_vel_hip")
if 特征2触发:
    triggered_features.append("head_hip_drop")
if 特征3触发:
    triggered_features.append("bbox_change")
if 特征4触发:
    triggered_features.append("hip_low")

# 共识机制：至少2个特征同时触发
if len(triggered_features) >= 2:
    is_fall_candidate = True
elif len(triggered_features) == 1:
    # 仅1个特征，不触发（防止误报）
    pass
```

### 为什么有效

| 场景 | 特征1 | 特征2 | 特征3 | 特征4 | 触发数 | 结果 |
|------|-------|-------|-------|-------|--------|------|
| **弯腰** | ❌ 角速度<3 | ❌ 髋部不降 | ❌ 宽高比<1.5 | ❌ 髋部不低 | 0 | 不报警 ✅ |
| **坐下** | ❌ 角速度<3 | ❌ 髋部不降 | ❌ 宽高比<1.5 | ❌ 髋部在椅子高度 | 0 | 不报警 ✅ |
| **真实跌倒** | ✅ | ✅ | ✅ | ✅ | 4 | 报警 ✅ |

## 六、完整判定流程

```
每帧检测
  ↓
关键点可见性检查（avg_visibility < 0.4 → 跳过）
  ↓
计算特征值：
  - 躯干角度 (torso_aci)
  - 角速度 (angular_velocity)
  - 头部下降速率 (head_drop_per_sec)
  - 髋部下降速率 (hip_drop_per_sec)
  - 宽高比变化 (bbox_ratio_change)
  - 髋部高度比例 (hip_height_ratio)
  ↓
坐姿检测（优先级最高）：
  - 髋部在椅子高度 + 角度25-70° → 坐姿
  - 宽高比≥0.7 + 角度<25° + 角速度<0.5 → 坐姿
  ↓
跌倒特征检测（多特征共识）：
  - 特征1: 角度>35° + 角速度>3° + 髋部降>100px/s
  - 特征2: 头降>30%身高/秒 + 髋部降>100px/s
  - 特征3: 宽高比>1.5x + 角度>35°
  - 特征4: 髋部<25%身高 + 角度>35°
  ↓
共识判定：
  - 触发特征数 ≥ 2 → is_fall_candidate = True
  - 触发特征数 < 2 → is_fall_candidate = False
  ↓
连续帧确认：
  - is_fall_candidate → fall_candidate_frames += 1
  - 否则 → fall_candidate_frames = max(0, -1)
  ↓
恢复检测：
  - 角度<25° 且 fall_candidate_frames > 0 → 清除候选帧
  ↓
报警判定：
  - fall_candidate_frames >= 5 → 触发报警
```

## 八、调试日志

程序运行时会在控制台输出调试日志：

```
[调试] 状态=站立 (Normal) 角度=15° 角速度=0.2 髋部=0.50 髋部降=10px/s 头降=0px/s 宽高比=0.55(1.05x) 候选帧=0 特征数=0 触发=无
```

**关键指标**：
- **状态**：当前判定状态（站立/坐姿/弯腰/跌倒）
- **角度**：躯干倾角（度）
- **角速度**：角度变化速率（度/帧）
- **髋部**：髋部高度占身高比例（0=头顶，1=脚底）
- **髋部降**：髋部下降速率（像素/秒）
- **头降**：头部下降速率（像素/秒）
- **宽高比**：当前宽高比（变化倍数）
- **候选帧**：连续满足跌倒条件的帧数
- **特征数**：当前触发的特征数量
- **触发**：触发的特征详情

## 九、已知问题和局限

### 1. 髋部高度检测依赖 bounding box 高度

`hip_height_ratio` 计算使用 `estimated_body_height_px`（历史最大 bounding box 高度），但人坐下后 bounding box 变小，可能导致计算不准确。

**缓解**：使用多特征共识，不单独依赖髋部高度。

### 2. 慢速跌倒可能漏检

角速度阈值提高到 3.0 后，老人缓慢跌倒可能角速度<3°/帧，导致漏检。

**缓解**：特征3（宽高比突变）和特征4（髋部过低）不依赖角速度，仍可检测慢速跌倒。

### 3. MediaPipe 髋部检测精度

MediaPipe 在某些角度下髋部关键点检测不准（如手放在桌子上遮挡）。

**缓解**：使用宽高比检测作为备选坐姿判定方案。

## 十、后续优化方向

### 1. 加权打分机制

给不同特征分配权重，总分超过阈值才报警：

| 特征 | 权重 | 说明 |
|------|------|------|
| 角度+角速度+髋部下降 | 3分 | 最重要 |
| 头降+髋部下降 | 3分 | 髋部下降是关键 |
| 宽高比突变 | 2分 | 辅助 |
| 髋部位置低 | 2分 | 辅助 |

**阈值**：总分≥5分才报警（需要至少2个重要特征）

### 2. 机器学习分类器

收集大量跌倒和日常活动数据，训练 SVM/Random Forest 分类器，替代手工规则。

### 3. 时序模型

使用 LSTM/GRU 等时序模型，学习动作的时间模式，更准确区分跌倒和日常活动。

### 4. 多摄像头融合

使用多个摄像头从不同角度检测，提高检测精度和鲁棒性。

### 测试场景

| 场景 | 预期结果 | 验证方法 |
|------|----------|----------|
| 正常站立 | 显示"站立"，不报警 | 摄像头观察 |
| 正常行走 | 显示"站立"或"活动中"，不报警 | 摄像头观察 |
| 慢慢弯腰 | 显示"弯腰/活动中"，不报警 | 摄像头观察 |

| 坐下坐稳 | 显示"坐姿"，不报警 | 摄像头观察 |
| 从站立慢慢坐下 | 可能显示"弯腰"，坐稳后变"坐姿"，不报警 | 摄像头观察 |
| 快速坐下 | 可能显示"弯腰"，坐稳后变"坐姿"，不报警 | 摄像头观察 |
| 真实跌倒（视频） | 显示"跌倒中"，触发报警 | 导入跌倒视频 |
| 平躺 | 显示"平躺"，可能报警（取决于角度） | 摄像头观察 |

### 调试方法

1. 启动程序后观察控制台输出
2. 重点关注"特征数"和"髋部降"指标
3. 如果误报，检查是哪个特征触发
4. 如果漏报，检查是否所有特征都没触发
